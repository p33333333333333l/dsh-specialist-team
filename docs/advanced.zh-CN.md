## 直接调用派工工具

在开启 Agent Teams 的主会话中调用 `spawn_teammate`。选择专家角色，填写交付物、可读写路径、可用工具、验收负责人和停止条件。给验收员派工时，列出它可以运行的完整命令。验收后由主代理负责整合改动。

名称须唯一，并以所选角色开头，例如 `researcher-read-docs`。使用小写英文字母和数字，各段用单个连字符连接，最长 32 个字符。如果创建时提示名称有误，检查角色前缀、格式，以及团队里是否已用了同一个名字。

需要共享主会话的对话记录时，使用 `context: fork`。省略可选模型字段时，优先使用角色设置，没有角色设置则沿用主代理的模型。空白模型字段按省略处理。直接指定模型时，同时传入 `provider` 和 `model`。如需传入 `reasoning_effort`，请使用该组合支持的推理强度。

工具和路径限制只约束已注册的工具调用。指派验收命令前，检查命令及其子进程能读取或修改哪些文件，以及是否会访问网络。专家和组长按自己会话的沙箱模式运行，`sandbox_permissions` 可以等于或窄于当前模式，更宽的模式会被插件拒绝。

专家或组长连续 3 次工具调用被拒绝时，插件会中断它这一轮的运行，并把最后被拒绝的工具和原因发给它的直接上级。中间只要有一次调用被放行，计数就清零。先排除阻碍或调整指派，再发消息让它继续。

## 关联任务卡与验收回执

创建原生任务卡后，可将任务 ID 填入 `spawn_teammate` 的 `assignment.task_id`。任务的依赖须已完成。专家启动后，插件会在任务板上把该卡指派给专家。未填写任务 ID 时，插件按派工的描述和交付物新建一张卡并指派给新成员，保证每个成员都有对应的卡。

每个专家都可以调用 `report_specialist_result`，填写 `status`、`summary`，以及适用的 `checks` 和 `limits`。`expected_failure`、`passed` 和 `failed` 由验收员使用，须列出实际执行的检查。其他状态为 `delivered`、`not_run` 和 `blocked`。回执对应成员自己的卡，通过原生消息发给直接上级。成员报告 `delivered`、`passed` 或 `expected_failure` 时，插件自动完成它新建的卡。主代理自己建的卡，由主代理审阅回执后在任务板上完成。

成员只能给直接上级发消息，组长还能给自己的直属成员发消息。成员有疑问先问上级，上级能答就答，答不了再往上转，只有主代理才会问用户。

## 按任务启用多级派工

用户可按任务启用多级派工。火力全开模式下，主代理默认采用多级派工。先确认 DSH 的子代理深度至少为 2，且整棵代理树至少有两个活动名额。层数跟随 DSH 的子代理深度：深度为 2 时是「主代理 → 组长 → 专家」，深度每多 1，组长就可以再开一层下级组长。若深度只有 1，主代理应说明限制，征得用户同意后再改用单层直派。

1. **主代理**为每个组建一张原生任务卡。依赖完成后，用 `spawn_specialist_coordinator` 启动组长。插件把组卡指派给组长，组长自行开始工作。
2. **组长**按获准的读写路径和验收命令拆解工作，用 `spawn_teammate` 启动专家。`max_specialists` 是该组整棵子树累计可启动的人数。专家只向本组组长回执。
   深度允许时，组长可以用 `spawn_specialist_coordinator` 分出下级组。下级组长沿用同一张组卡，读写路径和验收命令不能超出上级组长的范围，回执交给上级组长。开一个下级组长占 1 加它自己的 `max_specialists`，不能超过上级剩下的额度。如果下级组长开出来后已没有深度派专家，组长就不能再分组。
3. **组长**汇总实际检查、覆盖范围和阻塞项，发一份组回执。**主代理**审阅后完成组卡。

**名额紧张时**，插件在能读取上限的情况下，会限制新组长和下级组长的启动，给专家留一个名额。只有两个名额时，等当前组卡完成、组长退出，再启动下一组。其他队友也占用共享名额，DSH 会在每次启动时检查剩余容量。

**启动报错时**，先查看原生团队列表。已有组长就沿用它，必要时重新打开会话恢复组卡绑定。团队列表中没有该组长时，排除报错原因后可用同一张组卡重试。

## 手动修改配置文件

在当前配置的 `cordis.patch.yml` 中添加或更新 `dsh-team` 条目。把示例中的 ID 换成 DSH 允许使用的提供方和模型。

```yaml
- id: dsh-team
  config:
    coordinatorMode: 'off'  # off | full-power（旧值 strict 按 full-power 处理）
    models:
      researcher: { provider: YOUR_PROVIDER, model: YOUR_MODEL }
```

角色键可用 `designer`、`researcher`、`engineer`、`architect` 或 `verifier`。每个角色还可设置 `reasoningEffort`。通过设置页保存可能会移除所编辑 YAML 块中的注释。

## 恢复程序化工具调用

火力全开模式开启时，主代理使用原生工具调用。要恢复程序化工具调用（PTC），请关闭火力全开模式，再重新打开会话。
